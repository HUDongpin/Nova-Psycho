# 首次家长报告与逐次跟进

新建轮次使用 `parent_first_v1`。家长完成适用问卷并授权家长报告后，系统自动生成首次家长报告；学生和负责家庭的 TOPE 老师可在以后补充。每次新增来源生成独立版本，不改写已发布报告，不把新增来源解释成进步或退步。

## 现场操作

1. 家长从家长入口建档、分别选择参与测评、敏感资料及报告授权，填写家长简版。
2. 提交后等待自动生成，家长可阅读和下载报告。首次流程不要求学生或老师账号。管理员通过原有家庭分配功能指定负责老师。
3. 负责老师在家庭档案中查看报告，用原有跟进记录及支持目标记录沟通结果。
4. 后续学生用家庭编号加入。学生可选最多三句固定支持需要，预览并确认分享，也可以不分享而正常提交。普通答案及自由文字不会进入家长报告。
5. TOPE 负责老师从家庭页“开始现场观察”进入，不需要额外教师账号。填写现场观察、信息来源、支持及下一步。工作人员文字只在内部记录中展示。
6. 每补齐一方产生一个版本；通常为首次、一个中间版本、综合版。家庭页优先展示版本号最大的报告，历史版本可展开查看。新版失败时旧版仍可阅读；工作人员按具体任务重试，较新版本成功后仍可找回较早失败版本的重试入口。

家庭页在前台且本轮仍待补充时，每 15 秒检查另一账号的更新；离开该页面、隐藏窗口或三方都已提交后停止这项检查。已排队报告继续使用原有生成轮询及重试机制。

## 数据及接口

- 原有轮次的 `report_workflow` 默认为 `legacy_triad`，仍按三方齐全生成一次。新建轮次显式选择新流程，不批量改写旧轮次。
- 新版问卷：`growth-parent@2.1.0`、`growth-child@2.1.0`、`growth-tope-observation@1.0.0`。旧学校老师问卷继续供原轮次使用。
- 新轮次答卷提交后保持 `submitted`；报告状态属于 `report_jobs`。答卷、报告任务及 PDF 不再共用同一个唯一编号。
- 每个任务冻结来源集合和版本号，唯一约束按轮次及来源集合去重；版本号在家庭事务锁内分配。后完成的旧任务不会成为最新版。
- `Report.revision` 包含 `roundId`、`version`、`sourceAssessmentIds`、`sourceRoles`、`generatedAt`，并包含用于跨轮次排序的 `roundCreatedAt`。`Workspace.reportJobs` 提供阶段任务及是否可重试。
- `POST /api/families/:familyId/staff-observation` 开始或恢复负责老师的观察任务。服务端每次读取、保存及提交都检查账号、地区和家庭分配；重分配后原负责老师失去访问权限，未提交草稿保留给新负责人。
- `POST /api/report-jobs/:jobId/retry` 重试指定新版报告任务；旧单报告重试接口继续服务旧任务。
- 指定服务模式合成测试家庭仍须满足原有三个测试成员的严格范围；TOPE 观察人还必须是当前分配、有效且精确列入测试账号名单的工作人员，并使用测试会话。普通工作人员会话不获得该测试身份。此规则不放宽普通家庭的授权范围。
- 家长报告授权在生成、发布、读取、下载时生效。撤回后隐藏所有版本，恢复后继续符合条件的任务。

## 迁移与发布

本地初始化可使用 `scripts/setup.ts`；已有服务数据库使用有界迁移 `scripts/migrations/20261023-parent-first.ts`。环境通过私有配置提供，不在命令或日志中打印密钥。

```sh
node --import tsx scripts/migrations/20261023-parent-first.ts
node --import tsx scripts/migrations/20261023-parent-first.ts --apply
```

默认命令只检查。迁移新增版本列、部分唯一索引、轮次流程字段及新问卷；不会重算历史答案、报告或改动已有问卷状态。重复执行不重复插入。执行前核对区域、备份及当前运行版本。

此次数据库改动放宽“一份答卷一份报告”的唯一约束；旧代码的 `ON CONFLICT(assessment_id)` 与新结构不兼容。正式发布时须暂时停用写入口并暂停旧 worker，完成备份、迁移及新代码发布后再恢复入口和 worker。不能让旧代码继续写已迁移的数据库。回退应采用兼容新结构的修复版本；已有新版报告时不可直接恢复旧唯一约束或覆盖历史文件。

验收后再安排生产发布。发布后用获授权的合成家庭检查首次报告、两种补充顺序、旧报告下载及工作人员访问，并查看现有 ops 面板中的排队等待、失败和过期任务。未部署不代表线上行为已变化。

## 验证

- `npm test`、`npm run typecheck`、`npm run build`、`npm run lint`。
- `npm run test:integration`：原有 API、授权、历史三方流程及 PDF 回归。
- `tests/parent-first.integration.ts`：独立的本地 `nova_parent_first_*` 演示数据库，验证逐次版本、并发、乱序发布、授权恢复、定向重试及重新分配。此数据库测试直接调用 worker；它不代替自动发布验收。
- `tests/parent-first-migration.integration.ts`：从旧结构起步，验证检查模式、实际迁移、重复迁移、旧报告不变及区域拒绝。
- `tests/parent-first-synthetic-service.integration.ts`：完全在本地数据库运行服务模式，验证指定测试家庭与明确配置的 TOPE 测试老师；不调用线上服务或 AI。
- `tests/parent-first.browser.ts`：本地 3370／3371 端口的 CN／HK 演示服务和持续 worker；通过真实页面完成手机、桌面、简繁体场景，记录首次报告实际可见耗时，不手动调用 worker。

测试证据及私密 PDF 置于 `work/parent-first-20261023/`，不进入版本控制。所有测试均使用合成资料并关闭实时 AI。
